# 原生 PDF 阅读器增强计划

目标：围绕 Obsidian 原生 PDF 阅读器补齐"论文阅读"所需的能力。不改造阅读器本身，只做旁挂式功能（覆盖层、弹层、设置项）。

工作分支：main 上小步提交（每项一个 commit）。

## 实施原则

- 每完成一项更新本文档状态并附实现说明。
- UI 改动需在 Obsidian 中人工验证。
- 不触碰原生阅读器核心视图结构；新功能以覆盖层/弹层/工具栏形式叠加。
- 写回 PDF 时注意触发原生视图重载（见已实现的 `pdfAnnotationWriteback` 设置）。

## 实施记录

### ✅ P0：阅读位置记忆

- 设置项"PDF 打开时的位置"：上次浏览位置（默认）/ 从第一页开始。
- 记录：在原生视图容器上以捕获方式监听 `scroll`（滚动事件不冒泡但捕获路径可达），探针取"视口顶部 + 40px"所在页，停滚 2 秒后防抖写入 `paper.readingPosition = { page, updatedAt }`；插件卸载时强制落盘。
- 恢复：打开 PDF 后轮询 `.page[data-page-number]` 占位符（最多 30 × 120ms），出现后 `scrollIntoView({ block: "start" })`；原生视图全页占位，远页无需预先渲染。
- 落点：`src/main.js`（记录/持久化/恢复 + 滚动监听与清理）、`src/constants.js`、`src/settings.js`。
- **验证结果（2026-10-17）**：
  - "上次浏览位置"：✅ 通过（读到第 N 页 → 关闭 → 重开 → 回到第 N 页）。
  - "从第一页开始"：❌ **未通过**。切换设置并重启 Obsidian 后，打开论文仍停在之前的第 N 页。

### ⚠️ 未解决问题：`pdfOpenPosition=first` 不生效

**现象**：设置选"从第一页开始"后，从论文库打开 PDF 仍停在上次阅读的页码。

**已尝试的修复**：
1. 第一版：`restoreNativePdfReadingPosition` 在 `first` 模式下直接 return（不做任何滚动）。结果仍停在 N 页。
2. 第二版：`first` 模式下主动把第 1 页钉回顶部，打开后约 800ms 内反复检查纠正。
3. 第三版（当前）：钉回窗口延长至约 5 秒（大 PDF 加载后 Obsidian 才恢复视图状态），检测到用户交互（点击/滚轮/按键）立即停止；程序性定位期间抑制阅读位置记录 2.5 秒。
4. 均已构建并调用 `npm test` 通过，但**第三版尚未通过人工验证**（用户测试时可能未重新加载插件，也可能软链接 vault 首次启用）。

**后续排查建议**：
- 先确认实际运行的构建：测试 vault 用软链接指向仓库，改后必须重新加载插件。
- 开发者控制台（Cmd+Option+I）观察打开 PDF 后至第 5 秒之间是否有错误或滚动事件；在 `pinNativePdfToFirstPage` 里临时打日志，记录每次尝试时的 `attempt / pageTop / scrollerTop / interacting`。
- 确认 `data.json` 中 `pdfOpenPosition` 的实际值（应为 `"first"`）。
- 若 Obsidian 的恢复晚于 5 秒，考虑直接操作原生 PDF 视图的 view state（`leaf.getViewState()/setViewState()` 中的滚动字段），或在恢复后监听一次"idle"再定位。
- 排除对照：临时卸载其他可能记忆 PDF 位置的插件，确认不是第三方插件在恢复位置。

### ✅ P1：解释/翻译与标注回看

- 选区弹条在颜色后增加分隔线与"解释""翻译"两个图标按钮，复用 Ask AI 通道；提示词为英语：
  - 解释：`Explain this passage from the paper in clear terms.`（不指定回答语言）
  - 翻译：`Translate this passage into Chinese.`
- 标注回看：原生工具栏新增"标注列表"按钮，打开 `PdfAnnotationsModal`（`src/modals/annotations.js`）。按页码排序列出本文所有高亮（色点 + 页码 + 摘要），点击跳到原生阅读器对应页，每行可删除（走 `deletePdfMark` 的 canvas-highlight 分支）。跳页复用新增的 `scrollNativePdfToPage` / `openNativePdfAtPage`。

### 🔧 修复：不同 PDF 高亮颜色仍不均匀

部分 PDF（含数学/斜体等混合内联文字的排版）选区会产生高度差异大的重叠矩形，之前的"先合并矩形"判断失败后仍会叠色。改为**每个标注渲染为一条 SVG 路径**（`d` 由各矩形子路径拼接）：同一路径内的重叠区域按 nonzero 填充规则只填一次，multiply 仅作用于不同标注之间，从根上消除叠色。悬停命中检测改用 `isPointInFill`（带包围盒兜底）。覆盖层签名加版本前缀 `svg1|`，保证升级后旧 DOM 强制重绘。

### ✅ P2：默认颜色、数字快捷键、悬停气泡

- 默认高亮颜色：沿用已有的 `settings.defaultHighlightColor` 设置项（更新描述覆盖新用途），原生工具栏状态与画布视图的初始颜色都从这里读取，读取时统一小写归一。
- 选区弹条打开时按数字键 1-5 直接标对应颜色。
- 悬停覆盖层高亮时显示原文气泡（80ms 节流、按矩形命中检测、滚动/离开时隐藏）。覆盖层保持 `pointer-events: none`，不影响文字选择。
